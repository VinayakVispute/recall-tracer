2. Run it locally (about 5 minutes)

# 1. FalkorDB on port 6380
docker run -d -p 6380:6379 falkordb/falkordb

# 2. Install (root and web have separate package.json files)
bun install
cd web && bun install && cd ..

# 3. Env: copy and add the team Claude key
cp .env.example .env.local      # then set ANTHROPIC_API_KEY

# 4. Seed the graph (seed 42, same data every time)
bun run generate --seed 42 --reset

# 4b. Load the real FDA and CDC data into the separate "fda" graph
bun run real

# 5. API on :8787 and web on :3000
bun run dev

Check it works: open localhost:3000, or run curl -N 'localhost:8787/recall/replay?lot=L-204&speed=10'. You should see 22 events ending in done. Tests: bun run test (36 pass, 1 skipped) and bun run typecheck.

4. Deploy plan (B6)

Browser ──▶ Vercel (web/, Next.js) ──rewrites──▶ API container (Docker, port 8787) ──▶ FalkorDB Cloud RECALL_API=https://<api-host> ANTHROPIC_API_KEY, FALKORDB_*

Steps

  1. Add FalkorDB Cloud auth to src/graph/db.ts. Today it passes only host and port. Add username and password (and TLS if your Cloud instance needs it). Roughly: 
    FalkorDB.connect({
  username: process.env.FALKORDB_USERNAME,
  password: process.env.FALKORDB_PASSWORD,
  socket: { host: process.env.FALKORDB_HOST ?? 'localhost', port: Number(process.env.FALKORDB_PORT ?? 6380) },
})
    Check the option names against the falkordb client docs before relying on this. This file is in your lane ("auth fields only").
  2. Make the Dockerfile API-only. It still runs RUN bun run build, which builds web/, and its comment says it serves the page too. It doesn't any more: the web app is Next.js on Vercel. Root bun install does not install web/ dependencies (no workspaces), so that step will likely fail. Remove it and fix the comment.
  3. Host the API container anywhere that runs Docker and allows long responses (Fly.io, Railway, Render, a VM). Set ANTHROPIC_API_KEY and the FALKORDB_* vars. On start it seeds the graph if it is empty (generate --seed 42 --if-empty) and serves on $PORT. Add bun run real to the start command after generate, so GET /real/outbreaks has data. It reads committed JSON and needs no network.
  4. Create the Vercel project with root web/ and set RECALL_API to the API's public URL.
  5. Done when (from the plan): the public URL opens the dashboard, replay works with no key, and a live run works with the team key.

For local all-in-one: docker compose up runs FalkorDB plus the API (needs ANTHROPIC_API_KEY in .env).

6. Streams (SSE)

Every stream sends named events: event: <type> plus data: JSON. Listen with addEventListener(type), not onmessage.

EventData
start{model, lot} for a recall, {model, cluster} for an outbreak
note{text, turn}, the agent's reasoning text
tool_start{id, name, input, turn}
tool_end{call: {id, name, input, ms, db_ms, queries, cypher[], summary, error?, kind?}}
done{result} for a recall, {outbreak} for an outbreak. Close the stream here.
error{message}
const es = new EventSource(`/outbreak/stream?cluster=OB-2026-10`);
es.addEventListener('tool_end', (m) => addStep(JSON.parse(m.data).call));
es.addEventListener('done', (m) => { show(JSON.parse(m.data).outbreak); es.close(); });

Always close on done. If the stream ends without done, the browser reconnects and starts a second paid run. web/app/page.tsx already does this for recall: copy its pattern.

7. Gotchas

  • Long streams through Vercel. A live run takes 20 to 30 seconds. Streaming through the Vercel rewrite may hit a time limit or get buffered (a guess, not tested). Test one live /recall/stream on the deployed URL early. compress: false in next.config.ts is there on purpose: gzip makes SSE arrive in one chunk at the end.
  • Restarts keep the graph. The container seeds with --if-empty on boot, so incidents, ingested cases and lessons stay. Files in out/ (notices, live recordings) need a persistent disk at /app/out; Render has one. To start over, run bun run generate --seed 42 --reset in the Render shell.
  • Page 7 is empty on a fresh deploy until someone runs a recall.
  • /outbreak needs the Claude key. Without it, use the fixture or replay for the demo.
  • One transient error seen once. /outbreak/stream ended once with "Failed to process successful response". It didn't repeat in two reruns. Keep replay as the demo backup.
  • MCP isn't proxied. /mcp isn't in API_PATHS. MCP clients should call the API host directly.
  • Validate before you call Claude. The UI checks a lot with GET /incident/:lot/status before opening a stream. Do the same for clusters: POST /outbreak returns 400 or 404 before any Claude call.
